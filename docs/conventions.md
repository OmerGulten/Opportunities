# Engineering Conventions

Read this before adding code. It captures decisions that are easy to get wrong.

## Layers and ownership

* `src/app/**` is thin: resolve context, call a feature service, render. No business logic.
* `src/features/<domain>/` holds the domain's server services (`*.service.ts`), queries
  (`*.queries.ts`), Zod schemas (`*.schemas.ts`), server actions (`actions.ts`) and
  domain components (`components/`). Domain logic never lives in UI components.
* `src/lib/**` holds cross-cutting infrastructure and pure engines (scoring, credits,
  security, providers, workflows). No React in `lib` except `lib/i18n/client.tsx`.
* `src/components/ui` is generated by shadcn. `components/app` is the shell,
  `components/shared` are reusable domain-neutral pieces.

## Auth and tenancy (non-negotiable)

* Server Components: `const ctx = await requireWorkspaceContext()`; use `ctx.supabase`
  (RLS-scoped) for reads and writes. Never accept `workspace_id` from the client.
* Route Handlers: wrap with `withApi(handler, { body, query, role, rateLimit })` from
  `lib/api/with-api.ts`. Return `ok(data)` / `created(data)`. Throw `AppError`s.
* Server Actions: call `requireWorkspaceContext()` first, validate input with Zod, return
  `{ ok: true, data } | { ok: false, error: { code, message } }` (never throw to the client).
* Service-role client (`createAdminClient()`) only in workflow steps, `/api/internal`,
  admin server code after `requirePlatformAdmin()`, and for RPCs revoked from users.
  Always filter by a `workspace_id` you derived from a trusted row.

## Data quality

* Audits produce `Signal`s (for scoring) and `Finding`s (for humans). Use `makeSignal` and
  `makeUnavailableSignal` from `src/types/signals.ts`. Never emit `not_found` for something
  you did not check; use `not_checked` / `unavailable`.
* Every finding has `evidenceType` (`observed | derived | heuristic | unavailable`) and
  `confidence`. Heuristic performance results must say so.
* Neutral wording. "No website URL was found on the profile", not "has no website".

## i18n

* No hard-coded UI strings. Each feature owns `src/lib/i18n/messages/{tr,en}/<feature>.ts`
  (both files must have the same keys). `tr` is the primary language.
* Server: `const t = getT(ctx.locale, "scans"); t("wizard.title")`.
* Client: `const t = useT("scans")`. Params: `t("estimate.total", { count })`.
* DB bilingual columns: `pickLocalized(row, "name", locale)`.

## shadcn (base-nova style, Base UI primitives)

* Components import `cn` from `"cn"` (a tiny package) and use Base UI, not Radix.
* There is **no `asChild`**. To render a component as another element use the `render`
  prop: `<Button render={<Link href="/scans" />}>Scans</Button>`.
* `Select`: `<Select value onValueChange><SelectTrigger><SelectValue /></SelectTrigger><SelectContent><SelectItem value="x">X</SelectItem></SelectContent></Select>`.
  Items need non-empty string values.
* `Dialog`, `Sheet`, `AlertDialog`, `Popover`, `DropdownMenu`, `Tabs`, `Tooltip` follow the
  usual shadcn composition; check `src/components/ui/*.tsx` for exact export names.
* Forms: use `Field`, `FieldLabel`, `FieldDescription`, `FieldError` from `ui/field.tsx`
  with react-hook-form `Controller` when the form is complex; plain `Input`/`Label` for
  simple forms. There is no `ui/form.tsx`.
* Toasts: `import { toast } from "sonner"`.
* Charts: `ChartContainer` + Recharts from `ui/chart.tsx`.
* Icons: `lucide-react`.

## Styling

* Tailwind v4 with CSS variables from `globals.css`. Use semantic tokens
  (`bg-card`, `text-muted-foreground`, `border-border`). Dark mode is `.dark` class.
* Dense but airy: `text-sm` tables, `gap-4`/`gap-6` sections, `rounded-xl` cards.
* Status colours: emerald (good/found), amber (warning/ambiguous), rose (bad/error), slate
  (not checked/unknown), sky (info). Scores: >= 70 emerald, 40-69 amber, < 40 slate.

## Errors

* Throw `AppError` subclasses from `lib/errors`. Never surface stack traces.
* UI maps `error.code` through the `errors` i18n namespace.

## Providers

* Call external APIs only inside `lib/providers/*` or `lib/audits/*`, always through
  `safeFetchUrl()` for arbitrary URLs and through `timedProviderCall()` for observability.
* Never request Places fields outside `lib/providers/places/field-masks.ts`.

## Workflow DevKit

* `"use workflow"` functions are deterministic orchestration only: no DB, no fetch, no
  `Date.now()` outside steps (Date/Math.random are patched, but keep side effects in steps).
* `"use step"` functions do the work with the admin client. Throw `RetryableError` /
  `FatalError` from `"workflow"` appropriately. Set `step.maxRetries` where relevant.
* Steps must be idempotent (upserts on natural keys, `idempotency_key` for credits).

## Testing

* Vitest, tests next to the code as `*.test.ts`, fixtures in `tests/fixtures`.
* Pure engines (scoring, credits, safeFetch, dedupe, polygon, templates, state machine)
  need unit tests. Supabase-dependent code is tested through in-memory fakes of the
  minimal client surface it uses.

## Commits

Small, scoped commits with imperative subjects.
